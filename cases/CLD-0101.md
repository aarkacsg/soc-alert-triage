# CLD-0101 — Authentication Failures During Credential Rotation

## Alert
Repeated authentication failures were detected for a backup service account during an overnight maintenance window.

## Hypotheses
**Malicious:** An attacker may be attempting to brute-force the service account.

**Benign:** The failures may be caused by an approved credential rotation, with the service retrying the previous password.

## Evidence Reviewed
- Change record for the backup-platform credential rotation
- Authentication logs showing repeated invalid-credential failures
- All failures originated from the expected backup server
- A successful authentication occurred after the credential rotation completed
- No authentication attempts were observed from an unexpected source

## Verdict
**False Positive**

## Severity
**Informational**

The alert was initially treated as higher risk because repeated authentication failures can indicate brute-force activity. Investigation showed the behaviour matched an approved maintenance change.

## Action
- Close the incident
- Reference the approved change record
- Consider tuning the detection for approved credential-rotation windows without disabling the rule entirely

## Justification
The account, source system, timing and successful authentication after the maintenance activity all matched the approved credential rotation. No evidence of malicious authentication activity was identified.

## MITRE ATT&CK
Not applicable because the alert was determined to be a false positive.

## Key Learning
Repeated authentication failures should not be judged from the failure count alone. Change records, source systems and timing can provide critical context when distinguishing malicious activity from expected administrative behaviour.

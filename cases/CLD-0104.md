# CLD-0104 — MFA Failures Followed by Successful Sign-In

## Alert
An identity alert detected multiple MFA denials for a user account followed by a successful sign-in and registration of a new authenticator device.

## Hypotheses
**Malicious:** The user may be experiencing an MFA fatigue attack, with an attacker eventually gaining access and registering a new authenticator.

**Benign:** The user may be replacing a phone or reconfiguring MFA and generating several failed attempts before completing setup successfully.

## Evidence Reviewed
- Entra ID sign-in logs
- Five MFA denials before the successful authentication
- All activity came from the user’s normal Manchester office IP
- Device and browser matched the user’s usual Windows 10 and Chrome profile
- A new authenticator was registered shortly before the successful sign-in
- Helpdesk ticket HD-4471 confirmed the user was re-enrolling MFA on a new phone

## Verdict
**False Positive**

## Severity
**Informational**

The sequence initially resembled an MFA fatigue attack, but the authentication context and helpdesk record supported legitimate user activity.

## Action
- Close the incident
- Reference HD-4471 in the case notes
- No credential reset required
- Continue monitoring for authentication from unfamiliar locations or devices

## Justification
The source IP, device and browser all matched the user’s normal environment, and the helpdesk ticket confirmed legitimate MFA re-enrollment during the same time period.

## MITRE ATT&CK
Not applicable because the alert was determined to be a false positive.

## Key Learning
MFA denials followed by success can indicate an MFA fatigue attack, but the surrounding authentication context is critical. Device, location and helpdesk activity should be correlated before escalating the incident.
